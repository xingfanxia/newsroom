## Hard constraints (violating any of these re-pays hours — see HANDOFF)

- **Never** run `drizzle-kit push` against the live DB (false-diffs
  F32_BLOB → would drop `items.embedding` + the DiskANN index). New
  indexes/DDL go through raw-SQL ops scripts (`scripts/ops/db-optimize.ts`
  pattern, idempotent `IF NOT EXISTS`).
- **Never** bulk-`CREATE INDEX` on a vector column.
- Turso rejects `ANALYZE` → any new latency-sensitive query over
  items/clusters gets an `INDEXED BY` pin + a PLAN_CHECKS entry in
  db-optimize.ts.
- Large *write* batches run under `node --experimental-strip-types`, not bun
  (bun 1.3.1 corrupts big @libsql/client batches). Small writes (≤ dozens of
  rows) are fine under bun.
- Every prod-data mutation script: `--dry-run` default, `--apply` to write,
  idempotent, prints before/after counts.
- Branch `ax/audit-fixes` → PR → `bun run verify` green → merge. No direct
  pushes to main.
