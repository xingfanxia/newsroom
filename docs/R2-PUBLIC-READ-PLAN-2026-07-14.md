# R2 Public-Read Decoupling Plan

Status: final proposal, awaiting AX approval  
Date: 2026-07-14  
Goal: make anonymous read traffic structurally incapable of querying Turso,
while keeping total Turso reads below 100M rows/month and treating 10M/month as
the preferred operating target.

## Executive decision

Use Cloudflare R2 as the published public-content plane. Do not add Redis for
this problem.

Redis would improve repeated origin reads but would still leave a request-time
cache-miss path, per-request cache traffic, and a possible fallback to Turso.
The product data is generated by cron and is immutable between generation
events, so the stronger model is:

```text
content crons -> Turso -> incremental snapshot publisher -> immutable R2 objects
                                                        -> current.json pointer

anonymous HTML / JSON / RSS -> Cloudflare CDN -> R2 snapshot
authenticated writes/admin  -> application -> Turso
```

The invariant is not merely “usually cached.” It is:

> Every anonymous GET/HEAD route works with Turso credentials absent, including
> a cold application deployment and a cold CDN. A missing or corrupt snapshot
> may serve the last known good release or a controlled 503, but never queries
> Turso.

This makes Turso pressure a function of cron/publisher/private activity, not
anonymous request volume. Authenticated admin, user mutations, and bearer-token
agent activity remain separate explicit DB consumers.

## Claim audit

The previous agent was directionally right but too certain about attribution.

- Correct: `/en`, `/en/all`, and related HTML are currently dynamic/no-store,
  and public renders can reach Turso. This is a real traffic-scaled read path.
- Correct: the observed post-W9 rate is still above the 100M/month line; recent
  windows were roughly 240–290M/month, not the projected sub-100M steady state.
- Not proven: the residual is “almost entirely” one HTML query. Production
  request samples contain substantial `/api/mcp` traffic plus cron activity,
  and the Turso usage counter is not route-attributed.
- Not valid: reusing the old `~69k rows/render` W8 whole-page number as the
  current per-render cost. Subsequent calendar and query-cache changes altered
  that cost.

The new design removes the need to guess which public request is dominant: the
public import graph and poison-DB tests will prove that none can reach Turso.

## Scope and boundaries

### Must become snapshot-only

- Public HTML: home, all, curated, sources, podcasts, x-monitor, daily pages,
  and any public server component data they transitively load.
- Anonymous JSON: `app/api/public/*`, UI event-member and active-source reads,
  and other unauthenticated read endpoints.
- RSS/newsletter read routes.
- Public item/event/daily high-cardinality lookups.
- Read-only MCP resources/tools may reuse the snapshot to reduce total reads,
  but MCP bearer-token validation remains an authenticated DB concern unless a
  later auth project changes it.

### Explicitly outside the anonymous-read invariant

- Cron and snapshot publishing.
- Admin and authenticated private reads.
- Feedback, saved-items, tweaks, collections, and other user mutations.
- API-token accounting and `last_used_at` writes.

No route qualifies for the exception merely because it is expensive or hard to
migrate. The distinction is authentication/mutation, not implementation
convenience.

## Product decisions frozen by this plan

1. Anonymous lexical search remains available and moves to a snapshot-backed
   pure query engine.
2. Anonymous semantic search cannot be losslessly backed by R2 alone without
   publishing and scanning a large vector corpus. The default cutover is to
   return a documented unsupported-mode error for semantic search on the
   anonymous public endpoint and keep semantic search on bearer-authenticated
   v1/MCP surfaces. Preserving anonymous semantic search would be a separate
   Cloudflare Vectorize/Worker product decision, not a Turso fallback.
3. `/[locale]/saved` is private. Anonymous access must redirect to login or
   return 401, and the path must be removed from sitemap/robots exposure. The
   current fallback to `ADMIN_USER_ID` is both a privacy issue and a public DB
   read amplifier.
4. Calendar date links use `prefetch={false}`. A single `/all` visit currently
   fans out many RSC date requests; eliminating the fan-out is useful even after
   the DB is decoupled.
5. Snapshot eligibility is narrower than “row exists”: publish only enriched,
   non-excluded, intended-public records and canonical event leads. Never
   publish embeddings, raw LLM diagnostics/reasoning, raw RSS bodies, tokens,
   source-private notes, feedback, saved data, or user settings.
6. A runtime flag may support an explicit deployment-level `r2` versus `db`
   rollout during shadowing. There is never an `auto` request-time fallback.
   After the stability window, public DB mode is removed.

These are approval-time choices. Changing one after the goal starts requires a
new goal-version fingerprint rather than silent scope drift.

## Published object contract

Use a versioned namespace and content-addressed payloads:

```text
newsroom/v1/current.json
newsroom/v1/releases/<release-id>/manifest.json
newsroom/v1/objects/sha256/<hash>.json
newsroom/v1/objects/sha256/<hash>.xml
newsroom/v1/ops/runs/<yyyy-mm-dd>/<run-id>.json
```

`current.json` contains the schema version, active release and manifest hash,
publish time, source watermark, and the previous known-good release. It is
small and mutable. Target cache policy:

```text
public, max-age=15, s-maxage=30, stale-while-revalidate=300,
stale-if-error=86400
```

Manifest and content-addressed objects are immutable for one year. Stable
canonical serialization excludes volatile timestamps from content hashes, so
unchanged shards are reused rather than re-uploaded.

The manifest maps logical names to key, SHA-256, byte size, media type,
encoding, and shard metadata. Required logical artifacts include:

- shell aggregates and calendar counts;
- localized first-paint home/all/curated views;
- canonical public item metadata partitioned by month;
- item details and event members partitioned by stable ID bucket;
- sources/source health, podcasts, and x-monitor views;
- daily index and per-date columns;
- rendered feed/newsletter/legacy RSS;
- lexical-search shards;
- optional read-only MCP markdown resources.

Arbitrary feed parameters are evaluated by one pure query engine over canonical
metadata shards. The publisher must not attempt to pre-generate every possible
filter/tag/date/offset permutation.

## Incremental publisher contract

The publisher is the only new public-content module allowed to import the DB.
Its steady-state work must be proportional to changed public entities, not
traffic and not the entire corpus.

1. Add an append-only `public_content_outbox` with narrowly scoped SQLite
   triggers for public-relevant changes to items, clusters, sources/health,
   newsletters/dailies, and policy content. Install triggers before the
   bootstrap high-water mark so bootstrap-time writes cannot be lost.
2. Run a coalescing publisher shortly after content crons, initially at
   `12,27,42,57 * * * *`. A no-change tick reads only the small outbox/state
   surface and emits no release.
3. Capture the outbox maximum ID, deduplicate affected entity keys, and fetch
   only changed rows plus bounded dependent rows. Never execute a per-cluster
   N+1 query.
4. Patch the previous canonical state, derive all affected views/RSS/search
   artifacts in memory, hash them, and upload only changed objects.
5. Upload and validate all objects, then the immutable manifest. HEAD/GET and
   checksum/schema verification are mandatory.
6. Update `current.json` last, with ETag conditional write/CAS. A slower
   publisher cannot overwrite a newer release.
7. Delete outbox rows only through the captured maximum after the pointer
   succeeds. Rows created during publish remain for the next run.
8. Any failure leaves `current.json` and the outbox untouched. Readers continue
   to use the current or previous release.
9. Run a bounded daily reconciliation and a weekly garbage collector. Keep at
   least seven releases and 30 days of rollback data.

Bootstrap is separately budgeted and may perform one bounded full materialize.
It cannot be hidden inside a repeating cron.

Every run records duration, source watermark, candidate/scanned/returned rows,
changed entities, uploaded/reused shards, bytes, release ID, and failure stage
under `ops/runs/`. Publisher target is below 2M Turso rows/month; warning line is
5M/month.

## Reader and code ownership

Create a typed boundary such as:

```text
lib/public-content/contracts.ts
lib/public-content/paths.ts
lib/public-content/query.ts
lib/public-content/reader/*
lib/public-content/publisher/*
app/api/cron/publish-public/route.ts
scripts/ops/bootstrap-public-snapshot.ts
scripts/ops/publish-public-snapshot.ts
scripts/ops/check-public-db-boundary.ts
```

- Contracts are Zod schemas with inferred TypeScript types and an explicit
  `schemaVersion`.
- Reader modules use the public custom domain, verify pointer/manifest/payload
  hashes, and may use the previous release on corruption or timeout.
- Publisher/source modules own all Turso access and R2 write credentials.
- Public route adapters stay thin and preserve existing response envelopes,
  localization, ETags, pagination, and RSS formats except for the approved
  semantic-search change.
- A recursive import-graph check rejects every anonymous entrypoint that can
  reach `db/*`, `@libsql/client`, DB-owning live loaders, publisher code, or
  Turso environment names.
- A post-build `.nft.json` scan applies the same prohibition to anonymous
  server bundles. Direct-import lint alone is insufficient.

## Safe verification first

The current `bun run test` loads `.env.local`, which points at production, and
some suites perform real DB reads/writes. Bun async timeout failures have also
been observed with exit code 0. Running the existing full gate is therefore not
a valid or safe first step.

Phase 0 must make the default test/verify path hermetic:

- no production credentials are loaded by default;
- DB tests use a temporary local libSQL database or an injected fixture;
- R2 tests use an in-memory/local fake and a separately authorized integration
  prefix;
- production integration tests require an explicit opt-in flag;
- the gate detects timeout/failure output even if the runner exit code is
  misleading.

No implementation iteration may run the current production-backed test command
until this criterion passes.

## Rollout phases

### P0 — safety and observability

- Make tests hermetic.
- Protect `/saved`, remove it from public discovery, and disable calendar date
  prefetch.
- Record a fresh exact-window Turso baseline and public route inventory.
- Add publisher/read/load evidence directories and safe scripts.

### P1 — producer only

- Add contracts, sanitization, outbox/triggers, R2 adapters, atomic publisher,
  bootstrap, retention, and run telemetry.
- Publish to R2 without changing user traffic.
- Compare DB-derived fixtures to every snapshot contract and representative
  production samples from an operator-only job.

### P2 — public API and RSS readers

- Migrate public JSON, events, sources, items, dailies, and RSS to the snapshot
  reader.
- Preserve payload contracts and ETags; apply the approved semantic-search
  split.
- Reuse snapshots for read-only MCP content where possible, while keeping auth
  accounting explicit.

### P3 — public HTML readers

- Migrate home/all/curated/sources/podcasts/x-monitor/daily and dependent
  server components.
- Static/canonical routes may use Next ISR; query variants may remain dynamic,
  but every variant reads R2 only.
- Prove a deployment with no Turso credentials can serve the complete anonymous
  corpus.

### P4 — CDN and production cutover

- Re-verify the pre-provisioned Cloudflare Cache Rule against the real
  `current.json` and immutable release objects, including MISS-to-HIT behavior,
  `Age`, ETag, CORS, and distinct TTL semantics.
- Cut over route-by-route or through a canary. Shadow comparison is allowed in
  cron/operator jobs only; a public request must never dual-read DB and R2.
- Drill pointer rollback and application rollback. A rollback is an explicit
  operator action, not automatic DB fallback.
- Production publish/deploy/cutover requires explicit AX authorization after
  the local/preview gates pass.

### P5 — closure measurement

- Observe at least one complete publisher cadence and a 48-hour stable window.
- Run cold/warm/deploy/missing-object tests and 1x/10x/100x anonymous load
  replays against equal exact Turso windows plus no-load controls.
- Remove the public DB rollout mode and obsolete request-time DB caches after
  stability is proven.
- If total reads are below 100M but above 10M/month, decompose the remaining
  cron/auth/MCP floor and record a follow-up optimization inventory; do not
  misattribute it to public traffic.

## Acceptance contract

The implementation is complete only when all of the following are true in one
repo/deployment state:

1. Every inventoried anonymous GET/HEAD page, API, RSS route, and RSC follow-up
   has no transitive DB import and no DB fallback.
2. Those routes pass with valid snapshot fixtures and deliberately unusable or
   absent Turso credentials, including a cold build/runtime.
3. Snapshot schemas reject private fields and non-public records; unknown
   schema versions fail closed.
4. Publisher fault tests prove pointer-last atomicity, outbox high-water safety,
   idempotency, hash reuse, CAS concurrency, and last-good rollback.
5. A no-change publisher tick is O(1) on content rows, and changed work is
   O(changed entities); repeating full-corpus scans are forbidden.
6. API/RSS/HTML parity tests pass for locale, tier, cluster deduplication,
   source precedence, tags, date/range, pagination/total, sorting, item/event
   detail, and RSS formatting, except the approved semantic-search change.
7. `/saved` has no anonymous admin fallback, calendar prefetch is disabled, and
   public snapshot eligibility cannot widen item visibility.
8. Cloudflare returns a HIT with positive `Age` on the second eligible request;
   pointer and immutable-object caching behave according to their distinct
   TTLs.
9. 1x, 10x, and 100x anonymous sessions produce zero 5xx and no measurable
   increase in Turso rows versus equal no-load control windows. The result must
   also hold after cold deploy and cache miss; CDN warmth alone is not proof.
10. A clean exact 24-hour production window projects below 100M rows/month
    (`<136,986 rows/hour`). The preferred line is below 10M/month
    (`<13,699 rows/hour`); if it is not reached, closure must show the measured
    non-public residual and a bounded next plan.
11. Current architecture, ingestion, agent/API, testing, docs index, and
    handoff documents match the shipped ownership model and rollback runbook.

## Metered-resource policy for implementation

No plan or tier changes are authorized. Before any unattended integration run,
write-ahead the intended spend in the goal state and enforce these per-run caps:

- at most 500 R2 object writes;
- at most 10,000 public HTTP GET/HEAD requests;
- at most 1 GiB of uploaded/test-transfer payload;
- one separately recorded bootstrap snapshot;
- no production-backed test suite;
- no intentional Turso load outside a named exact measurement window.

Over-cap work is logged and deferred, never silently spent and never converted
into an interactive prompt. Production publish/deploy/cutover, any future
DNS/cache-rule mutation, or the user-visible semantic API change remains an
explicit external gate.

## Rollback

- Data rollback: conditionally point `current.json` at the previous verified
  manifest.
- Application rollback: abort/roll back the deployment while the previous R2
  releases remain available.
- R2 failure: use the reader's last known good release and stale headers, or
  return controlled 503. Do not query Turso.
- Publisher failure: leave pointer and outbox intact; retry on the next bounded
  run.
- Cache Rule failure: disable or correct the rule without deleting objects.

The supplied R2 writer credentials should be rotated if their scope is broader
than this bucket. After the production env is verified, delete the plaintext
download or move it into the password manager; the implementation never needs
to read it again.
